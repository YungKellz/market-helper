# Market Helper

Десктоп-приложение под Windows 11: определяет товар по фотографии и генерирует
продающее описание карточки для Авито. Вся генерация идёт **локально** — фото и
тексты не покидают машину.

## Как это работает

Пайплайн из двух шагов, оба на одной мультимодальной модели:

1. **Распознавание.** Фото нормализуются (EXIF-поворот, ресайз до 1024 px,
   JPEG q85) и уходят в vision-модель. На выходе — структурированные факты:
   тип товара, бренд, модель, состояние, видимые дефекты, прочитанные надписи,
   уровень уверенности и вопросы к пользователю.
2. **Копирайтинг.** Факты + характеристики, введённые руками, + профиль
   продавца превращаются в заголовок, описание и поисковые фразы. Текст
   стримится в интерфейс по мере генерации.

Поверх результата работает детерминированный линтер (`src-tauri/src/pipeline/lint.rs`):
он ищет то, что модели забывают, — контакты, ссылки, упоминания других площадок,
цену в заголовке, капс, необоснованные превосходные степени, выход за лимиты длины.

## Что вшито в промпт: ресерч по продающим описаниям

- В поисковой выдаче видны только фото, заголовок, цена и **первые ~200 символов**
  описания — хук обязан отвечать «что это, в каком состоянии, почему стоит открыть».
- Рабочий диапазон длины — **800–1500 символов**. Технический максимум поля куда
  больше, но длинные тексты не дочитывают.
- Заголовок — **до 100 символов**, только товар, бренд, модель и один-два
  ключевых параметра. Цена в заголовке запрещена правилами площадки.
- Каждая характеристика переводится в выгоду («аккумулятор 5000 мА·ч — двое суток
  без розетки»), текст разбивается на короткие абзацы и списки.
- Честное перечисление дефектов повышает конверсию в сделку и снижает отказы
  на встрече.
- Ключевые фразы вплетаются в живой текст: свалка ключей в конце понижает
  объявление в выдаче.
- Полностью запрещены контакты в описании: телефоны, e-mail, ссылки, ники в
  мессенджерах.

## Стек

- **Tauri 2** + Rust — окно, IPC, работа с процессами и изображениями
- **React 19 + TypeScript + Vite** — интерфейс
- **Гибридный инференс**: Ollama, если она запущена; иначе поднимается
  собственный `llama-server` из llama.cpp

## Требования

- Windows 11
- Rust (toolchain **MSVC**), Node.js 20+, pnpm
- Visual Studio Build Tools 2022 и WebView2 Runtime
- Для инференса — [Ollama](https://ollama.com) либо собственный `llama-server` +
  GGUF-модель с mmproj-файлом

### Модели

| Модель | VRAM | Комментарий |
| --- | --- | --- |
| `qwen3-vl:8b` | 8+ ГБ | по умолчанию, лучшее качество |
| `qwen3-vl:4b` | ~6 ГБ | быстрее, текст чуть проще |
| `qwen2.5vl:3b` | ~4 ГБ или CPU | минимальные требования |

```bash
ollama pull qwen3-vl:8b
```

Модель можно скачать и прямо из приложения — «Настройки» → «Скачать».

## Разработка

```bash
pnpm install
```

```bash
pnpm tauri dev
```

Сборка установщика (NSIS):

```bash
pnpm tauri build
```

## Структура

```
src/                      интерфейс на React
  api.ts                  типизированные обёртки над invoke
  components/             панели: фото, факты, характеристики, результат, настройки
src-tauri/src/
  config.rs               настройки приложения, профиль продавца
  imaging.rs              EXIF-поворот, ресайз, JPEG, base64
  llm/                    абстракция бэкенда: ollama.rs, llamacpp.rs
  pipeline/
    prompts.rs            промпты с вшитым ресерчем по Авито
    lint.rs               проверки текста по правилам площадки
    schema.rs             структуры фактов и карточки
  commands.rs             команды Tauri
```
