# Caption Craft

Десктоп-приложение под Windows 11: определяет товар по фотографии и генерирует
продающее описание карточки для Авито. Вся генерация идёт **локально** — фото и
тексты не покидают машину.

Название — от «camera-ready copy» наоборот: снимок на входе, готовая
подпись к нему на выходе.

## Как это работает

Пайплайн из двух шагов, оба на одной мультимодальной модели:

1. **Распознавание.** Фото нормализуются (EXIF-поворот, ресайз до 1024 px,
   JPEG q85) и уходят в vision-модель. На выходе — структурированные факты:
   тип товара, бренд, модель, состояние, видимые дефекты, прочитанные надписи,
   уровень уверенности и вопросы к пользователю.
2. **Копирайтинг.** Факты + характеристики, введённые руками, + профиль
   продавца превращаются в заголовок, описание и поисковые фразы. Текст
   стримится в интерфейс по мере генерации.

Поверх результата работает детерминированный линтер (`src-tauri/src/pipeline/lint.rs`):
он ищет то, что модели забывают, — контакты, ссылки, упоминания других площадок,
цену в заголовке, капс, необоснованные превосходные степени, выход за лимиты длины.

## Что вшито в промпт: ресерч по продающим описаниям

- В поисковой выдаче видны только фото, заголовок, цена и **первые ~200 символов**
  описания — хук обязан отвечать «что это, в каком состоянии, почему стоит открыть».
- Рабочий диапазон длины — **800–1500 символов**. Технический максимум поля куда
  больше, но длинные тексты не дочитывают.
- Заголовок — **до 100 символов**, только товар, бренд, модель и один-два
  ключевых параметра. Цена в заголовке запрещена правилами площадки.
- Каждая характеристика переводится в выгоду («аккумулятор 5000 мА·ч — двое суток
  без розетки»), текст разбивается на короткие абзацы и списки.
- Честное перечисление дефектов повышает конверсию в сделку и снижает отказы
  на встрече.
- Ключевые фразы вплетаются в живой текст: свалка ключей в конце понижает
  объявление в выдаче.
- Полностью запрещены контакты в описании: телефоны, e-mail, ссылки, ники в
  мессенджерах.

### Сценарий под товар: парфюмерия и косметика

Один усреднённый промпт хорошо продаёт б/у технику, но для парфюма и
косметики выдаёт пресную «комиссионку»: там решает не состояние, а аромат,
оригинальность и свежесть. Поэтому этап копирайтинга выбирает сценарий по
распознанной категории (`ProductClass` в `src-tauri/src/pipeline/prompts.rs`):

- **Beauty** (мисты, лосьоны, кремы, духи, гели). Хук сразу называет тип,
  линейку/аромат, объём и «оригинал»; отдельные блоки — аромат (ноты и
  характер), формат и применение с честной оговоркой про стойкость,
  оригинальность и свежесть (происхождение, запечатан/вскрыт,
  тестер/полноразмер, срок годности), ассортимент под кросс-продажу. Запрещено
  приравнивать мист к eau de parfum, обещать лечебный эффект и выдумывать ноты,
  объём или страну.
- **Generic** — прежний сценарий для всего остального: характеристики,
  состояние с дефектами, «характеристика → выгода».

Класс определяется по ключевым словам категории, типа и бренда; при сомнении
выбирается Generic, чтобы чувственные описания аромата не попали на не-парфюм.
Заполненный в форме раздел «Парфюмерия и косметика» сам по себе включает Beauty.

Под нишу в форме характеристик есть отдельный раздел «Парфюмерия и косметика»
(`BeautyAttributes`): происхождение, тип аромата, ноты, срок годности, состояние
упаковки, а также флаги «пришлю фото батч-кода по запросу» и «другие ароматы — в
профиле». Эти поля — данные продавца: модель их не выдумывает, а только
раскладывает по блокам описания.

## Стек

- **Tauri 2** + Rust — окно, IPC, работа с процессами и изображениями
- **React 19 + TypeScript + Vite** — интерфейс
- **Гибридный инференс**: Ollama, если она запущена; иначе поднимается
  собственный `llama-server` из llama.cpp

## Установка для обычного пользователя

1. Скачать `caption-craft_0.1.0_x64-setup.exe` из релиза и запустить — обычный
   установщик, «Далее → Готово». Около 10 МБ.
2. При первом запуске откроется мастер: он сам ставит движок Ollama (через
   `winget`, без окон и без прав администратора), запускает его и качает модель.
   Одна кнопка «Установить и скачать», прогресс виден по шагам.
3. Дальше приложение работает без интернета.

Движок и веса намеренно не вшиты в установщик: дистрибутив вырос бы до 6–8 ГБ,
а обновление модели требовало бы пересборки приложения. Если `winget` в системе
нет, мастер скачивает официальный установщик Ollama и открывает его — пользователь
проходит его шаги и возвращается в окно.

Мастер можно закрыть кнопкой «Позже»; тогда в шапке останется кнопка
«Завершить установку».

## Обновления

Приложение при запуске тихо проверяет GitHub Releases и, если вышла новая
версия, показывает полосу под шапкой: одна кнопка скачивает, ставит поверх
и перезапускает. Неудача проверки — нет сети, нет релиза — ничего не
показывает: пользователь её не заказывал.

Выпуск новой версии:

```bash
pnpm release -- --notes "Что нового"
```

Скрипт собирает установщик, подписывает его, кладёт рядом `latest.json`
и создаёт релиз через `gh`. Перед запуском поднимите `version` в
`src-tauri/tauri.conf.json` — на существующий тег скрипт откажется работать.
Проверить всё, не выкладывая ничего наружу: `pnpm release -- --dry-run`.

Три вещи, которые стоит знать заранее.

**Приватный ключ подписи лежит в `~/.tauri/caption-craft-updater.key` и никуда
не копируется.** Если его потерять, доставить обновление уже установленным
копиям будет нельзя никогда — только рассылать установщик руками. Ключ
создан без пароля, то есть защита у него ровно одна: сам файл.

**Артефакты переименовываются.** Tauri берёт имя файла из `productName`,
а там пробел. GitHub заменяет во вложениях всё, кроме латиницы, цифр,
точки, дефиса и подчёркивания, — пробел стал бы точкой, ссылка
в `latest.json` не совпала бы с настоящим адресом и обновление молча
не находилось бы.

**Скрипт написан на Node, а не на PowerShell, намеренно.** Ключ без пароля,
и Tauri ждёт пустое значение в `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, а
PowerShell удаляет переменную окружения при присвоении пустой строки —
сборка доходит до подписи и виснет на приглашении ввода без единого
сообщения.

## Требования для разработки

- Windows 11
- Rust (toolchain **MSVC**), Node.js 20+, pnpm
- Visual Studio Build Tools 2022 и WebView2 Runtime
- Для инференса — [Ollama](https://ollama.com) либо собственный `llama-server` +
  GGUF-модель с mmproj-файлом

### Модели

| Модель | VRAM | Комментарий |
| --- | --- | --- |
| `qwen3-vl:8b` | 8+ ГБ | по умолчанию, лучшее качество |
| `qwen3-vl:4b` | ~6 ГБ | быстрее, текст чуть проще |
| `qwen2.5vl:3b` | ~4 ГБ или CPU | минимальные требования |

```bash
ollama pull qwen3-vl:8b
```

Модель можно скачать и прямо из приложения — «Настройки» → «Скачать».


## Структура

```
src/                      интерфейс на React
  api.ts                  типизированные обёртки над invoke
  components/             панели: фото, факты, характеристики, результат, настройки
src-tauri/src/
  config.rs               настройки приложения, профиль продавца
  imaging.rs              EXIF-поворот, ресайз, JPEG, base64
  llm/                    абстракция бэкенда: ollama.rs, llamacpp.rs
  pipeline/
    prompts.rs            промпты с вшитым ресерчем по Авито
    lint.rs               проверки текста по правилам площадки
    schema.rs             структуры фактов и карточки
  commands.rs             команды Tauri
```
